# Technocratic UI Principles (v0.1)

## Definition

**Technocratic** here means: the interface behaves like a clear operating system for travel decisions—hierarchies, states, and data are legible; vibes are structured, not chaotic.

## Principles

1. **Segment is structure, not decoration**  
   Home, filters, trip cards, analytics, and pricing bands all hang off the six product lines.

2. **Density without clutter**  
   Prefer scannable tables, chips, and status rows over large empty hero wallpaper.

3. **Explicit states**  
   Draft · Live · Full · Waitlist · Completed · Cancelled — always visible where relevant.

4. **Progressive disclosure**  
   Summary first (price, dates, seats, match %); detail on expand/trip page.

5. **Trust is a first-class surface**  
   Verification, policies, group composition, emergency affordances never buried in footers only.

6. **Explain matching**  
   Never show a score without reasons.

7. **Equal structural weight for six segments**  
   Visual tokens differ; layout system stays consistent.

8. **Growth vs trust**  
   When UI choices trade conversion for clarity/safety, choose trust.

## Anti-patterns

- Infinite destination carousels before segment choice  
- Hidden fees until last checkout step  
- “People nearby” maps that leak CodeHouse addresses or couple privacy  
- Festival FOMO dark patterns (fake scarcity without real inventory)  

## Accessibility baseline

- WCAG AA contrast on text/chips  
- Keyboard path for book + join  
- Do not encode segment only by color
