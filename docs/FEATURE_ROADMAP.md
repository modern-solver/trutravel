# TruTravel — Scaffolding Feature Roadmap

**A build-order map of every feature the platform is scoped to ship, from the current vertical slice through the September 2026 launch and beyond.**

Generated by the orchestration hub · 2026-08-10 · Source of truth: `docs/architecture/platform-architecture.md`, `docs/agents/backlog.md`, `docs/agents/shared-context.md`, `packages/db/prisma/schema.prisma`, and the A/P/T/G agent roster.

> **How to read this.** Every feature is tagged with a **status**, an **owner** (agent ID from the frozen swarm roster), and a **milestone**. Status legend:
> `✅ Built` — implemented and verified in the codebase today · `🟡 Partial` — scaffold/contract exists, real implementation pending · `⬜ To build` — not started · `🔒 Locked out` — deliberately excluded (founder/legal decision).

---

## 1. Where the build is today

The repo is a **modular-monolith monorepo** (`npm` workspaces, TypeScript end-to-end):

```
apps/web/            Next.js 14 (App Router) — the vertical slice's HTTP surface (pages + API routes)
packages/domain/     Framework-free domain logic: identity, catalog policy, matching, booking, events
packages/db/         Prisma schema, client singleton, seed data, hard DB-level constraints
```

**One vertical slice is live (TKT-010, milestone M3):** Himachal (Manali + Bir) × Thrilling Tours **and** × Trippy Tours, sharing one domain model with two segment catalogs. What exists: the full data model, the matching engine (hard gates + soft score + composition preview + overrides), the booking state machine skeleton, real HMAC session auth with a platform-wide 18+ gate, and 8 API routes wired to real domain + DB logic (no mock handlers).

**What is explicitly *not* built yet** is the entire monetization, analytics, hardening, QA, and UI layer — plus four of the six product segments. That is the substance of this roadmap.

## 3. Milestone sequencing to launch

The founder-set target is **September 2026**, with **independent launch gates** — Thrilling and Trippy each ship when individually QA-ready; there is no combined go/no-go.

| Milestone | Theme | State | Critical remaining work |
|---|---|---|---|
| M0 | Foundations | ✅ Closed | — |
| M1 | Specs & guardrails | ✅ Closed | — |
| M2 | Design | ✅ Closed | Composition-preview format confirmation (minor, P3→P2) |
| M3 | Build | 🟡 In progress | Architecture ✅ done (TKT-010). **Remaining: T2 payments, T3 analytics, T4 devops, T5 QA, FE screens** |
| M4 | Supply | ⬜ Queued (TKT-011) | 8–12 trips + captains onboarded; insurance partner live; operator onboarding |
| M5 | Launch | ⬜ Target Sept 2026 | QA-gated go-live per segment; ToS/waiver legal drafting |
| M6 | Scale | ⬜ Undefined | Second corridor/segment without collapsing India depth |

**Critical path to September:** `payments (T2)` + `frontend screens (FE)` + `devops/CI (T4)` + `QA (T5)` run in parallel on top of the finished M3 architecture, while `supply onboarding (G2/G1)` and `insurance (G4)` fill the catalog — all gated by `QA sign-off (T5)` per segment.

## 4. Cross-cutting risks & open decisions (from the backlog)

These are flagged in `docs/agents/backlog.md` / `docs/ops/risk-register.md` and gate real features above:

1. **ToS/waiver legal ownership is unassigned** — the accepted-risk safety path (TKT-016) depends on a legally sound waiver, but no agent owns India ToS drafting. Short runway against a Sept target. *(Founder decision.)*
2. **Insurance timeline** — G4's referral/group-policy path could be ready by Sept if outreach starts immediately; P1 conservatively cut high-altitude routes pending it. *(Founder to reconcile.)*
3. **Margin guardrail** — Thrilling breaches the 18% contribution floor above ~12.5% refund rate (weather-driven trek cancellations are a real exposure). T2's incentive-cap enforcement must be built, not assumed.
4. **Composition-preview format** — data layer supports either shape; P3 still owes P2 a format confirmation. Narrow, non-blocking.
